## P01. 제품과 자금 경계

모임·정모·번개의 회비를 외부 송금하고 앱에서 요청·납부 신고·입금 확인·지출·환불·이의를 기록한다. 앱 포인트, 충전, 현금화, 플랫폼 에스크로는 사용하지 않는다. 앱의 확인 상태는 외부 이체 완료를 자동 증명하지 않는다. 실제 송금은 사용자가 외부 앱/계좌에서 수행한다.

## P02. 참여와 차수

- 모임 안에 정모/번개, 이벤트 안에 차수를 둔다. 정모는 모임장·관리자, 번개는 부원이 주최한다. 공개 번개에는 비부원도 참여한다.
- 정원 내 신청은 즉시 확정, 초과 신청은 대기. 주최자가 신청 마감 때 확정자를 선정·탈락시키지 않는다. 인원 조정은 대화로 취소를 요청한다.
- 차수별 신청 마감과 회비 요청을 분리한다. 사전 걷기는 각 차수 마감 때 확정자에게 해당 차수 회비를 요청한다. 납부 기한은 주최자가 차수별로 지정한다.
- 마감 후에는 본인 합류 요청 → 주최자 승인 → 해당 차수 명단 추가·회비 요청. 기존 참여자에게 다시 요청하지 않는다.
- 미납이어도 참여는 유지한다. 주최자는 대화로 납부·취소를 요청한다. 기한 경과만으로 자동 취소·대기 승격하지 않는다.
- 정산 방식은 이벤트 개설 시 사후 정산 또는 사전 걷기 중 선택한다. 신청 마감은 두 방식에서 참여 명단을 다루며, 사후 정산은 마감 시 선납 요청을 만들지 않는다.

## P03. 납부·부분 입금

외부 송금 → 참가자 납부 신고 → 주최자의 실제 입금 확인. 상태는 미납/확인 대기/부분 납부/완납이다. 반려 사유와 확인 이력을 남긴다. 부분 납부는 실제 확인액을 누적하고 잔여액만 요청한다. 30,000원 요청에 10,000원 확인이면 잔여 요청은 20,000원이다. 같은 입금을 중복 확인하지 않는다.

기한 판정은 실제 입금 시각 기준이다. 앱 신고·주최자 확인이 늦었다고 참가자를 감점하지 않는다. 실제 시각 미확인·분쟁은 판정 보류. 승인된 연장 기한은 해당 납부 요청에 적용한다.

## P04. 취소·노쇼·일정 변경

- 차수별 취소 비용을 신청 전에 고지한다. 참가자 취소와 노쇼는 같은 비용을 적용한다. 미설정은 0원이다.
- 이미 납부했다면 비용만 차감 후 환불, 전액 미납이면 기존 회비 대신 취소 비용만 청구한다. 원 회비와 중복 청구하지 않는다.
- 주최자가 차수를 취소하면 전액 환불. 날짜 변경은 재참여 의사를 확인하고 불참자는 비용 없이 전액 환불한다.
- 신청 후 취소 비용 변경은 기존 신청자 재동의 후 적용한다. 거부자는 비용 없이 취소 가능. 미응답자는 참여 유지·동의 대기, 새 비용 미적용, 주최자가 대화로 확인한다.
- 비용 적용 시점은 가입 시 고지한 조건과 동의 버전에 연결한다. 임의 소급 부과하지 않는다.

## P05. 지출과 최종 정산

지출 항목명·금액·차수는 필수, 영수증/이체내역은 선택. 미첨부는 ‘증빙 없음’. OCR은 필수가 아니다.

차수별 실제 지출에서 실제 수령한 취소·노쇼 비용을 빼고, 해당 차수 참석자끼리 분담한다. 계산식은 `참석자 총부담 = max(0, 차수 지출 - 수령 취소·노쇼 비용)`이다. 개인별 조정은 지출 총액과 일치해야 한다. 정산 분담의 원 단위 나머지는 고정된 참가자 순서로 1원씩 배분하여 합계를 맞춘다(구현 기본값; 화면에서 근거 표시).

사전 회비는 차수별로 요청하지만 **최종 정산은 이벤트 전체의 개인별 부담액·납부액·기지급 환불을 합산**한다. `추가 요청 = max(0, 최종 부담 - 확인 입금 + 지급 환불)`, `환불 = max(0, 확인 입금 - 지급 환불 - 최종 부담)`. 같은 사람의 1차 환불 5,000원과 2차 추가 부담 3,000원은 합산해 2,000원 환불한다. 참여하지 않은 차수는 부담시키지 않는다.

취소 비용 수령액이 지출을 넘으면 참석자 부담 0원, 초과금은 비용 납부자에게 납부 비율대로 환불한다. 이 환불액의 원 미만은 버리고 나머지만 모임 적립금으로 넘긴다. 같은 비율 3명에게 10,000원 반환이면 각 3,333원, 적립 1원이다.

취소 비용 미수금은 우선 차감하지 않는다. 나중에 받으면 이벤트 담당자가 추가 환불 또는 모임 적립을 선택하고 참석자에게 금액·결과를 알린다. 일반 환불 미수령액을 적립금으로 바꾸지는 않는다.

참석자 0명이어도 지출·수령 취소 비용·환불을 기록하고 정산한다. 참석자 나누기만 생략한다. 고지 취소 비용으로 충당되지 않는 지출은 주최자 부담으로 표시하고 불참자에게 고지액을 초과해 청구하지 않는다.

## P06. 마감·정정·이의

이벤트 종료 후 72시간 이내 최초 정산을 등록한다. 참가자 전원 납부나 이의 해결 완료 기한과는 별개다.

계산 마감은 미납·환불·이의 의무 종료가 아니다. 미납이나 이의가 있어도 마감 가능하며 남은 요청·기록·처리 기능을 유지한다. 이후 입금은 후속 기록으로 추가한다. 마감 후 오류는 원본을 보존하고 정정 기록을 추가한다. 기납부자 차액 환불, 미납자 요청액 조정, 영향을 받는 사람에게 안내한다. 정정 증액도 최종 순차액 계산에 반영한다.

이의는 납부와 병행 가능. 인정·반려·철회·정정의 사유/처리자/시점을 남긴다. 이의 중 즉시 감점하지 않는다. 주최자 무응답은 모임장 대리 요청→미해결 시 운영자, 주최자가 모임장이면 운영자 직접 요청한다.

## P07. 주최자·인계·계정 삭제

- 일반 부원 주최자도 자기 이벤트의 수금·환불·이의·정정 권한과 홈 할 일을 가진다. 모임 관리자 역할과 별개다.
- 모임 탈퇴 후에도 본인 주최 이벤트의 정산 책임과 처리 권한은 유지한다. 일반 모임 활동 권한과 분리한다.
- 서비스 계정 삭제는 본인 담당 업무 완료 또는 담당자 인수·잔여금 실제 인계 확인 후 가능. 계산 마감만으로 완료 처리하지 않는다.
- 인수자는 모임장·관리자 또는 해당 이벤트 참여자 중 수락한 사람. 해당 이벤트 정산 권한만 받는다.
- 인수 수락→인계 내역·금액 등록→외부 송금→새 담당자의 실제 입금 확인→권한 이전. 잔여금 0원은 내역·0원 확인으로 완료. 기존 주최 이력은 보존한다.

## P08. 적립금·해산

- 모임별 외부 보관 계좌 1개. 모임장·관리자 중 실제 계좌 관리자인 1명을 입금 확인 담당자로 지정한다.
- 적립 전환 선택→이벤트 담당자 송금→보관 담당자 실제 입금 확인 때 적립 완료·잔액 반영. 앱은 자금을 보관하지 않는다.
- 사용은 모임장·관리자만 가능. 목적·금액 등록→계좌 담당자 실제 송금/출금 확인→사용 완료·잔액 차감. 담당자 본인 사용도 실제 거래 후 완료한다. 이벤트 정산 권한과 분리한다.
- 부원 전체가 잔액·적립 출처·사용 목적·금액·처리자·일시를 열람한다. 개인 계좌의 다른 거래는 공개하지 않는다.
- **해산 잔여 적립금은 모임장에게 귀속**한다. 기여자 비례 반환안은 채택하지 않는다. 귀속 지급/정리와 실제 확인을 기록해 잔액 0원·입출금 확인 완료 후 해산한다. 같은 계좌라 외부 송금이 없더라도 귀속 정리 근거·확인을 기록한다.
- 담당자를 유지하고 이벤트 계산을 마감하면 미납·환불·이의가 남아도 모임 해산 가능. 의무·처리 기능과 정산/적립금 기록은 유지한다. 미지급 참가자 환불을 적립금으로 바꿔 귀속시키지 않는다.

## P09. 가입·신원·이름

가입은 카카오/구글/애플 소셜 로그인+SMS 전화번호 인증. 실명·CI 확보를 전제하지 않는다. 예금주 확인은 계좌 등록 때 별도. 이미 등록된 전화번호로 다른 소셜 가입을 시도하면 자동 병합/연결 없이 차단하고 기존 로그인 사용을 안내한다.

가입 방식은 즉시/승인제. 모임별 닉네임 필수. 초대는 일반 가입의 승인을 생략하지만 강퇴 이력자는 초대 경유여도 승인 필수다. 블랙리스트는 해당 모임 가입·공개 번개 신청·마감 후 합류 요청을 차단하며 다른 모임에는 영향 없다. 자동 승인 처리도 이 차단/강퇴 우선순위를 우회하지 않는다.

정산·채팅은 닉네임만 표시. 부원은 모임별, 공개 번개 비부원은 서비스 닉네임. 변경하면 과거 화면도 현재 닉네임으로 표시하되 같은 사용자 ID에 연결한다. 탈퇴 후 마지막 닉네임+‘탈퇴한 멤버’. 송금에 필요한 예금주명은 송금 맥락에서 별도 표시한다.

## P10. 공개·신고·차단

| 정보 | 허용 열람자 |
|---|---|
| 개인별 부담·납부·잔여·확인 상태 | 이벤트 미참여자를 포함한 모임 부원 전체 |
| 일반 지출 증빙 | 이벤트 미참여자를 포함한 모임 부원 전체 |
| 이의/분쟁 상세·대화·송금 캡처 | 당사자·해당 건 처리 담당자만 |
| 이의 진행 상태·결과·정정 금액 | 모임 부원 전체 |
| 모임 레벨 | 같은 모임 부원 또는 같은 이벤트 참여자 |

탈퇴자·공개 번개 비부원은 자기 참여 정산의 계산 근거·기록 열람과 납부·환불 확인·이의 처리를 유지한다. 일반 모임 콘텐츠 권한까지 부여하지 않는다. 팔로우해도 비가입 모임의 내부 글·공지·내부 이벤트를 볼 수 없다. 개인 글·공개 번개의 허용 정보만 노출한다.

차단은 피드·개인 채팅에 적용하고 정산 명단·송금·환불·이의 접근은 유지한다. 모임 글/댓글은 모임 관리자 1차→미해결 운영자. 개인 글·사용자 신고, 모임장/관리자가 신고 대상인 건은 운영자 직접 처리.

## P11. 알림·홈·채팅

소셜 알림은 유사 건을 묶고 정산·송금·환불·이의는 개별 표시. 모든 종류의 푸시는 사용자가 끌 수 있다. 푸시를 꺼도 인앱 알림함과 업무 기록은 유지한다. 알림센터는 공통 알림 모듈이 소유하고 홈 벨에서 진입한다(코드 소유의 구현 결정).

홈은 정산 할 일·날짜 선택·다가오는 일정. 마이는 과거 정산 내역·모임 레벨·프로필·설정. 마이의 일정/돈 액션 중복 배치는 제거한다. 정모/번개는 홈 +와 모임 화면 양쪽에서 공통 작성 화면을 사용하고 모임 진입은 소속 모임을 사전 선택한다.

채팅 탭은 개인·모임 상시방·정모/번개방을 종류 구분해 최근 메시지순으로 통합한다. 모임/이벤트 상세에서도 같은 방에 접근한다. 참가 확정 전 합류 요청/대기는 이벤트방 자동 입장 사유가 아니다.

## P12. 모임 레벨

초기 50점·0~100점, 신규 ‘이력 없음’. 참가 납부와 주최 최초 등록 이력을 반영한다.

| 판정 | 변화 |
|---|---:|
| 기한 내 납부 완료 | +1 |
| 실제 입금 시각으로 지연 확인 | -2 |
| 지연 납부 완료 | +1 회복(순변화 -1) |
| 종료 후 72시간 내 최초 등록 | +2 |
| 최초 등록 기한 초과 | -4 |
| 지연 후 최초 등록 | +2 회복(순변화 -2) |

이벤트·역할별 1회, 정상/회복 중복 가점 없음. 부분 납부/차수/정정 횟수로 중복 가점하지 않는다. 실제 시각 미확인·이의·판정 불가 장애는 감점 보류, 오류는 정정한다. 금융 신용등급이 아니다.

## P13. 무응답·운영자

처리 요청 24시간 미응답 재안내, 72시간 미응답부터 모임장 대리 요청 가능. 모임장도 대리 요청 후 72시간 동안 처리/진행 안내가 없으면 운영자로 상향 가능. 주최자가 모임장이면 바로 운영자에게 요청. 운영자 최초 회신 목표는 72시간으로, 해결/환불 완료 보장이 아니다.

운영자는 필요한 증빙·양측 소명 확인, 결과/근거 기록, 정정/인계 요청, 콘텐츠 조치·경고·필요한 이용 제한을 한다. 강제 외부 송금이나 증빙 없는 입금 완료를 수행하지 않는다. 이용 제한과 기존 정산 접근은 분리한다.
