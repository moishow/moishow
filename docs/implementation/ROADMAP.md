## 이번 실행 범위

문서·와이어프레임·HTML/JPEG 목업의 현재 기준은57개 화면/12흐름이다. 서버 기반·계정·정산·인계·운영은 develop에 통합했고 현재 issue/16-mobile에서 Flutter·실제 API 연결을 검증한다. 서버 최신168개 테스트 통과를 앱 실기기/공급자 완료로 확대하지 않는다.

서버는 사용자 선택에 따라 Spring Boot/Java로 진행한다. [기술 기준](../architecture/TECH-STACK.md)과 [Spring 실행 계획](SPRING-BOOT-PLAN.md)을 따른다. 기존 ESM/Node 코어 PR17은 정책 대조용으로 병합·보존했고 운영 계산은 Java로 이식했다. 실제 Flutter 프로젝트는 apps/mobile에 있으며 공통 토큰·실제 REST/STOMP·보호 파일·영속 재시도·계정별 세션을 연결했다. 화면별 실제 수락과 남은 공급자/단말 한계는 MOBILE-APP.md에서 확인한다.

## 브랜치·리뷰

- main: 사용자 승인 정책·설계·배포 가능한 문서/목업. 직접 변경은 이번 정본 동기화 요청에 한해 승인됐다.
- develop: main 최신 기준을 포함하며 이슈 PR의 기본 대상이다. 기존 dev/design·kyung·mypage는 보존한다.
- 이슈 브랜치는 develop에서 만든다. 관련 이슈·수용 기준·테스트를 연결한다. 서버13~15의 실제 교차 검증은 PR21에 통합했으며, 앱16은 별도 PR/CI/독립 검토로 진행한다.
- 완료하지 않은 API/외부 송금/DB 작업은 완료 체크하지 않는다. 목업의 링크 이동과 실제 처리 API를 구분한다.

## 공통 개발 인수 기준

정수 원화·안전 정수 검증, 금액 보존, 개인별/차수별 분담 근거, 부분입금·환불 이력, 중복/동시 요청, 사용자 ID 기반 권한, 마감 후 append 정정, 실확인 전 잔액 미반영, 닉네임/분쟁 증빙 권한 분리, 푸시 off 인앱 유지, 운영자도 실제 현금 인계 위조 불가.

## 계정·DB 구현 인수 (이슈12)

PR19 Spring 기반과 PR20 계정/DB를 develop에 병합했다. PostgreSQL/Flyway/JPA·세션/OTP/소셜 검증 어댑터·모임 운영/이벤트 주최/참가 상태 권한과 중복/버전 처리를 구현했고 PR21에서 금융·운영 원장을 연결했다. 앱16 후속의 모임 소개·거절 이력·정확 송금 안내와 V11까지 서버168개 전체 검증 통과했다. [실제 API 범위와 운영 전제](IDENTITY-API.md)를 따르며 provider 실자격/수신·실기기·배포 검증은 별도다.
