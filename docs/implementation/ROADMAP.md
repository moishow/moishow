## 이번 실행 범위

문서·와이어프레임·HTML 목업·PNG와 인수 기준을 main에 정렬하고, develop에서 1번 이슈 브랜치를 시작한다. 전체 앱은 화면 목업만으로 운영 완료라 하지 않는다.

서버는 사용자 선택에 따라 Spring Boot/Java로 진행한다. [기술 기준](../architecture/TECH-STACK.md)과 [Spring 실행 계획](SPRING-BOOT-PLAN.md)을 따른다. 기존 ESM/Node 코어 PR #17은 정책 대조용으로 보존하며, 운영 서버의 계산은 이슈 #18에서 Java로 이식한다. Flutter 테마는 디자인 참고이며 앱이 생성된 것은 아니다. 서버 기초와 순수 계산 이후 DB·인증·채팅을 이슈별로 연결한다.

## 브랜치·리뷰

- main: 사용자 승인 정책·설계·배포 가능한 문서/목업. 직접 변경은 이번 정본 동기화 요청에 한해 승인됐다.
- develop: main 최신 기준을 포함하며 이슈 PR의 기본 대상이다. 기존 dev/design·kyung·mypage는 보존한다.
- 이슈 브랜치는 develop에서 만든다. 관련 이슈·수용 기준·테스트를 연결하고 한 이슈당 작은 PR로 검토한다.
- 완료하지 않은 API/외부 송금/DB 작업은 완료 체크하지 않는다. 목업의 링크 이동과 실제 처리 API를 구분한다.

## 공통 개발 인수 기준

정수 원화·안전 정수 검증, 금액 보존, 개인별/차수별 분담 근거, 부분입금·환불 이력, 중복/동시 요청, 사용자 ID 기반 권한, 마감 후 append 정정, 실확인 전 잔액 미반영, 닉네임/분쟁 증빙 권한 분리, 푸시 off 인앱 유지, 운영자도 실제 현금 인계 위조 불가.
